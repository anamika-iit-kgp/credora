Data stays where it lives

  • • Bank data is read in place. Oracle goes through the Oracle virtual schema, MySQL and PostgreSQL through adbc-vs-rs
  • • 3rd party data (CIBIL, GSTN, Account Aggregator) is fetched on demand via API from HTTPS relays on credora.link
  • • Raw API replies are staged with a purge time and deleted with SHA-256 proof

One call does the analysis

  • • RUN_ANALYSIS (Lua) runs 13 logged steps in 17.5 s for 1,000 companies
  • • The risk model is trained and scored inside Exasol on 5,000 past loans
  • • PREFERRING ranks approved companies on return, risk and size at once

The database enforces access

  • • Each web role logs in as its own Exasol user. RMs see a masked view
  • • Ask Credora reads as the signed-in role's Exasol user, semantic layer first
  • • Offers and the negotiation trail are written to the bank's crm database
